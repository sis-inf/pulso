## Retrospectiva del sprint
**Lo que funcionó bien:**
- El uso de GitHub Actions para automatizar pruebas fue muy eficaz.
- Las reuniones diarias de 15 minutos mantuvieron el equipo alineado.
- El enfoque en pruebas unitarias desde el inicio redujo errores críticos.

**Áreas de mejora:**
- La documentación técnica para nuevos miembros podría ser más detallada.
- Algunos desarrolladores reportaron sobrecarga en el manejo de dependencias.
- La planificación de tareas podría incluir más tiempo para integraciones.

**Próximos pasos:**
- Mejorar el proceso de revisión de código para acelerar el merge.
- Iniciar el sprint 3 con un enfoque más centrado en la documentación.
- Establecer un sistema más claro para la asignación de tareas.
